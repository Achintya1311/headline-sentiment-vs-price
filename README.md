# Headline sentiment vs price

Educational research on historical data. Not investment advice. Not a SEBI-registered research analyst.

**Question:** does scored headline sentiment correlate with the stock's own contemporaneous or next-day return, once the timestamp alignment is leak-free?
**Method:** align each headline to the first trading session its own publish time permits, score it with VADER, and correlate against contemporaneous and lagged open-to-close return (Fisher-z 95% CI), with a shuffled-timestamp permutation audit as the correctness gate.
**Finding (Day 5, null result):** contemporaneous r = -0.185, 95% CI [-0.555, +0.246], n=23 — a CI that comfortably contains zero. Low resolution too: 17 of 23 headlines saturate at the same VADER score, leaving little independent variation to explain. See Findings and "Why this null result might be spurious anyway" below.
**Chart:** `outputs/sentiment_price_overlay.png` — cumulative return for the 3 high-magnitude headlines, with the aligned session marked.
**Reproduce:** `python -m sentiment.correlate`

Scores financial headlines and tests them against subsequent returns, with a leakage control that has to fail before any result is believed.

## What this is

Scrapes headlines with timestamps, scores them with VADER as a baseline and FinBERT as the finance-tuned upgrade, then tests correlation and predictive power out of sample.

The hard part is not the model, it is the timestamp alignment. A headline stamped 09:20 is not tradable at the 09:15 open, and getting that wrong is how these projects quietly lie. It gets its own stage and its own control test.

## Correctness gate

Shuffled-timestamp control: randomise headline times and the signal must disappear. `sentiment.audit` (Day 8) implements this - it re-runs Day 5's actual alignment and price-lookup code under thousands of random re-timings, not just a stats-only reshuffle of two already-computed number lists, and reports a permutation p-value for the real pairing against that null.

This is the test that decides whether the repo is finished. A result that has not passed it is a draft. It runs automatically in `tests/test_audit.py` (part of `pytest`, so every change to the alignment or correlation code re-checks it), and `.github/workflows/ci.yml` now runs the full suite plus `sentiment.audit`/`sentiment.leakage_audit`/`sentiment.robustness` on every push and pull request (P16) - not only when the CLI is run once by hand. See Limitations for what CI still doesn't exercise.

## How to run

```bash
uv venv && source .venv/bin/activate
uv pip install -r requirements.txt

# Day 1: scrape headlines. Offline by default - reads the committed
# fixtures/rss/*.xml snapshots, so nothing blocks on network access.
python -m sentiment.scrape
python -m sentiment.scrape --live                       # real fetch, robots.txt + rate limit enforced
python -m sentiment.scrape --feed economic_times_markets --live
# Runs on its own now too: .github/workflows/collect-headlines.yml does the
# second command daily (only the allowed feed), committing new headlines
# when there are any and staying quiet when there aren't (holiday, no news).

# Day 2: VADER baseline scorer + evaluation harness. Fully offline - the
# VADER lexicon is vendored under sentiment/lexicons/, not downloaded.
python -m sentiment.score                                # scores fixtures/headlines/headlines_raw.csv
python -m sentiment.score --in path/to.csv --out path/to_scored.csv
python -m sentiment.evaluate                              # accuracy vs fixtures/eval/vader_eval_set.csv

# Day 3: FinBERT scorer + VADER/FinBERT agreement analysis. Needs torch,
# installed separately as a CPU-only wheel (see requirements.txt), and a
# network connection the first time only, to download the model:
uv pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m sentiment.finbert                               # scores fixtures/headlines/headlines_raw.csv with FinBERT
python -m sentiment.agreement                              # VADER vs FinBERT: corpus agreement + eval-set accuracy
# .github/workflows/finbert-sentiment-contract.yml runs this repo's own
# torch-free sandbox around: GitHub Actions installs the CPU-only wheel
# weekly, runs sentiment.finbert, then sentiment.contract --model finbert
# --ticker INFY.NS, and commits the result to fixtures/sentiment/INFY.json
# (first run on push of the workflow itself, not only on the weekly cron).

# Day 4: timestamp alignment. Maps each headline to the first trading
# session whose own open happens after it was published - no live data,
# pure calendar logic against IST market hours.
python -m sentiment.align                                  # aligns fixtures/headlines/headlines_raw.csv

# Day 5: contemporaneous vs lagged correlation + event study. Offline by
# default - reads the committed fixtures/prices/*.json snapshots (one
# ticker's daily OHLC each, fetched once from Yahoo Finance's free public
# chart endpoint, no API key). --live re-fetches and overwrites them.
python -m sentiment.correlate
python -m sentiment.correlate --live
python -m sentiment.correlate --event-threshold 0.3

# Day 6: next-day return regression, split by time, evaluated out of sample
# only. Reuses Day 5's contemporaneous/lagged pairing; fits on the earliest
# --train-frac of usable headlines (by publish time) and reports predictive
# metrics on the held-out, later-published rest only.
python -m sentiment.regress
python -m sentiment.regress --train-frac 0.6

# Day 7: sentiment-price overlay and cumulative abnormal return charts.
# Writes two PNGs to outputs/ (gitignored, per the CLI-only/no-dashboard
# rule - charts are files, not a server). Reuses Day 5's build_rows and
# Day 5's --event-threshold grouping.
python -m sentiment.overlay
python -m sentiment.overlay --live
python -m sentiment.overlay --window-before 8 --window-after 2

# Day 8: timestamp-shuffle leakage audit. Rebuilds Day 5's contemporaneous
# correlation under thousands of randomised headline-timestamp re-pairings
# (reusing the real alignment + price-lookup code, fixture-only by default)
# and reports a permutation p-value for the real pairing against that null.
python -m sentiment.audit
python -m sentiment.audit --n-perm 5000
python -m sentiment.audit --live
# Day 8, second control: the same shuffle applied to the Day 5 lagged correlation
# and the Day 6 out-of-sample regression, which sentiment.audit does not cover.
python -m sentiment.leakage_audit
# Day 8, third control: reverse causality, market-wide shocks, feed timestamp integrity.
python -m sentiment.robustness
```

This repo is offline-only, against committed fixtures, and no code here reads an API key or needs one at any day: RSS feeds are public, the VADER lexicon is vendored, FinBERT (`ProsusAI/finbert`) is a public HuggingFace model, and Day 5's `sentiment/prices.py` price fetch is yfinance's free public chart endpoint, keyless like the rest of the portfolio.

**Day 1 - RSS scraper.** Three feeds registered, one actually reachable from this sandbox:

- `economic_times_markets` (economictimes.indiatimes.com): robots.txt allows the RSS path, live fetch succeeds. 50 headlines scraped and snapshotted to `fixtures/rss/economic_times_markets.xml` - this is real, current data, not synthetic. - `moneycontrol_business` (moneycontrol.com): fetching moneycontrol's own `robots.txt` returns HTTP 403. Per RFC 9309, a 401/403 on robots.txt itself means "assume full disallow" - `RobotsCache` does exactly that and the feed is skipped, never fetched. No fixture exists for this feed because it has never been legitimately scraped.
- `reuters_business` (feeds.reuters.com): unreachable from this sandbox (proxy returns a 502 on the CONNECT tunnel). `RobotsCache` fails closed on any connection error while reading robots.txt, so this also comes back "denied" rather than attempting the feed anyway. No fixture exists for the same reason.

Storage is CSV, not the parquet the scaffold's "How to run" section assumed - neither `pyarrow` nor `fastparquet` is available in this sandbox and nothing else in the portfolio uses parquet either, so `fixtures/headlines/headlines_raw.csv` is the real format going forward. The `sentiment.analyse --fixtures ...parquet` line above is Day 3+ scaffold text, not yet true.

**Day 2 - VADER baseline scorer and evaluation harness.** `sentiment.vader_score` wraps NLTK's `SentimentIntensityAnalyzer` against a vendored copy of the lexicon (`sentiment/lexicons/vader_lexicon.txt`, ~92 KB, see `NOTICE.md` there) so scoring never needs `nltk.download()` at run time - verified by moving the sandbox's own downloaded copy aside and re-running the full suite and both CLIs, which behaved identically. `python -m sentiment.score` scores all 50 committed headlines (standard VADER thresholds: compound ≥ 0.05 positive, ≤ -0.05 negative, else neutral) - 29 positive / 16 neutral / 5 negative, mean compound +0.17. That skew is itself a finding, not a market signal: the evaluation harness below shows VADER over-reads routine corporate-action language ("approves", "announces") as positive.

`python -m sentiment.evaluate` runs the scorer against a 24-row hand-labeled set (`fixtures/eval/vader_eval_set.csv`) split into three categories and reports accuracy overall and per category:

| Category | Accuracy | What it tests |
|---|---|---|
| `general` (14) | 14/14 (100%) | headlines whose tone lives in everyday sentiment words - VADER's home turf |
| `neutral_factual` (4) | 3/4 (75%) | routine, tone-free corporate notices |
| `finance_jargon` (6) | 0/6 (0%) | tone that lives in finance-specific phrasing a general lexicon can't read |

Overall: 17/24 (70.8%). The `finance_jargon` column is the headline result, and it is exactly the caveat NEXT_STEPS.md already flagged: `"Company beats earnings estimates, raises full-year guidance"` scores `0.0` (neutral) despite being unambiguously bullish, and `"Manufacturer recalls product over safety defect"` scores *positive* because "safety" is a positive lexicon word with no notion that "safety defect" reverses it. This is the gap Day 3's FinBERT scorer and the VADER/FinBERT agreement analysis exist to close - not a bug in this scorer, VADER working exactly as documented.

**Day 3 - FinBERT scorer and VADER/FinBERT agreement analysis.** `sentiment/finbert_score.py` wraps `ProsusAI/finbert` (a BERT model fine-tuned on the Financial PhraseBank) via HuggingFace `transformers` + CPU-only `torch`. Unlike VADER's vendored lexicon, the ~440 MB model weights are not committed to this repo - they are pulled from the HuggingFace Hub on first use and cached under `~/.cache/huggingface`, so Day 3 needs network access once, then runs offline. `python -m sentiment.finbert` scores all 50 committed headlines: 15 positive / 25 neutral / 10 negative, mean derived score (positive − negative probability) +0.072 - far more neutral-heavy than VADER's 29/16/5, because FinBERT does not treat routine "Share Price Highlights" roundup headlines as sentiment-bearing the way VADER's lexicon does.

`python -m sentiment.agreement` runs both comparisons NEXT_STEPS.md asked for:

- **Corpus agreement** (50 scraped headlines, no ground truth): VADER and FinBERT agree on only **38%** of labels. The single biggest driver is mechanical, not a modeling disagreement: 13 headlines follow the pattern `"<Company> Share Price Highlights: <Company> Stock Price History"`, and VADER scores every one of them positive (compound +0.296, apparently from "Highlights") while FinBERT correctly reads them as neutral (no sentiment content at all). Strip that pattern out and the disagreement is still substantial - the two models are measuring different things, which is exactly why an agreement number alone would be misleading without looking at *where* they disagree.
- **Eval-set accuracy** (24 hand-labeled headlines, ground truth from a human): FinBERT scores 91.7% overall vs VADER's 70.8%, and the category breakdown shows why - `finance_jargon` accuracy goes from VADER's documented 0/6 (0%) to FinBERT's 6/6 (100%), closing the exact gap Day 2 found (`"Company beats earnings estimates, raises full-year guidance"` now reads positive; `"Manufacturer recalls product over safety defect"` now reads negative). That is not a clean sweep, though: FinBERT drops slightly below VADER on `general` (92.9% vs 100%), misreading `"Bank shares rally on rate cut hopes"` as negative - an honest miss on a headline VADER's everyday-sentiment lexicon gets right, worth naming rather than glossing over the one category where a finance-tuned model loses to a general-purpose one.

**Day 4 - timestamp alignment.** `sentiment/market_hours.py` maps every headline's `published_at` to a `session_date`: the first NSE trading day whose 09:15 IST open happens strictly after the headline was published, so no aligned session's return can include price action that predates the news. Three cases collapse to one rule (`align_headline`): a headline is aligned to *today* only if today is a trading day and the headline arrived before today's open; every other case (during the session, after the close, or on a weekend/holiday) rolls forward to the next trading day. `Alignment.leak_free()` asserts the invariant directly - the session's open is strictly after the local timestamp - rather than trusting the classification logic that produced it, and `sentiment.align`'s CLI asserts it on every row before writing.

Run against the real 50-headline fixture (all real Economic Times timestamps from Monday 28 Sep 2026, not synthetic): 21 pre-open, 21 intraday, 8 post-close - a genuine spread across all three cases, not a corner case invented for the test. The exact trap NEXT_STEPS.md names shows up in the real data: a headline timestamped 09:20:57 IST (`"Shah Investor's Home IPO opens today..."`) is intraday, not pre-open, and aligns to Tuesday the 29th, not Monday the 28th it was published on - the same headline naively bucketed by calendar date alone would wrongly get credited with (or blamed for) Monday's full-day return, most of which happened before it existed.

`python -m sentiment.align` writes `outputs/headlines_aligned.csv` (original columns plus `local_time`, `timing`, `session_date`) - Day 5's correlation and event-study work reads `session_date` to know which day's return each headline may honestly be tested against.

**Day 5 - contemporaneous vs lagged correlation, event study.** `sentiment/tickers.py` maps a headline to exactly one NSE ticker only when the headline is genuinely about one company - the "Share Price Highlights" liveblog template and "`<Company>` shares rise/fall N%" headlines, not a screener-list headline like "Cyient among 4 stocks showing White Marubozu Pattern" (Cyient there is one example among several, not the subject). Of the 50 fixture headlines, 24 name exactly one company this way; 23 of those resolved to a real Yahoo Finance ticker via `sentiment/prices.py` (free public chart endpoint, no key, same source the rest of the portfolio uses via yfinance) - `LTIM.NS`/`LTIMINDTREE.NS` both 404 for LTIMindtree and no other symbol was found, so it's excluded and named in the CLI's own output rather than guessed. One resolution surprise worth recording: `NSE shares fall 2%...` refers to the National Stock Exchange's own listed shares, which trade under `NSE.BO` on the BSE, not `NSE.NS` on the NSE itself - the naive same-exchange guess 404s.

For each of the 23, `sentiment.correlate` computes a **contemporaneous return** (the aligned `session_date`'s own open-to-close - the first return the market had available to react with, per Day 4's leak-free construction) and a **lagged return** (the next trading session's open-to-close). Both are correlated against VADER's `compound` score with a 95% CI (Fisher z-transform), and an event study splits headlines into "high-magnitude" (`|compound| > 0.3`) vs the rest and bootstraps a 95% CI on the difference in mean contemporaneous return.

The honest result is a null one, and a low-resolution one before it's even a null one: 17 of the 23 resolved headlines - every "Share Price Highlights" template headline plus a few of the move headlines - score exactly `compound = 0.296`, because VADER's normalization saturates to the same value for short headlines with a similar count of mildly-positive words, "Highlights" among them, regardless of whether the underlying move was up or down (`Suzlon Energy shares fall 2%...` scores the identical `+0.296` as `PC Jeweller shares rise 4%...`). With most of the sample pinned to one value, there is barely any independent variation for a correlation to explain before the price side is even considered. Against that ceiling: contemporaneous r = -0.185, 95% CI [-0.555, +0.246], n=23 - a CI that comfortably contains zero. Lagged return could only be computed for the 15 headlines aligned to Monday 28 Sep (Tuesday-aligned headlines' lagged session is Wednesday 30 Sep, which had not traded yet as of this run): r = +0.000, 95% CI [-0.512, +0.512], n=15. The event study's high-magnitude group (Fortis Healthcare, Great Eastern Shipping, Max Financial - the only 3 headlines whose sentiment content goes beyond the template) has n=3 against n=20 for the rest; mean return diff = -0.0095, 95% CI [-0.0354, +0.0130]. None of this supports a signal, and with n this small and a sample this saturated at one score, it could not have - the finding is that this fixture, as scraped, cannot yet answer the question, not that the answer is "no correlation."

**Day 6 - next-day return regression, split by time, evaluated out of sample.** `sentiment/regress.py` fits a single-predictor OLS line (`sentiment/stats.py`'s new `ols_fit`) of next-day return (Day 5's `lagged_return`) on VADER `compound`, using only the 15 headlines a next-day return could be computed for. The split is chronological, not random or k-fold: `sentiment.correlate.build_rows` already returns headlines in `published_at` order, so the earliest `--train-frac` (default 0.7) is genuinely the past relative to the held-out rest - fitting on a random split here would let a later headline leak into an earlier prediction, the same look-ahead class of bug Day 4 exists to prevent. Every reported predictive number - out-of-sample R² (Campbell-Thompson style, benchmarked against the *training* mean, not the test set's own mean) and MAE against a "always predict the training mean" baseline - comes from the 5-headline held-out test split only; in-sample numbers are printed for comparison but are explicitly not the result.

The honest result is sharper than Day 5's saturation finding, and more structural: **every one of the 15 headlines with a next-day return shares the identical `compound = 0.296`.** This is not a coincidence of small-sample bad luck - it traces directly to which headlines got a next-day return at all. All 15 are "Share Price Highlights" template headlines aligned to Monday 28 Sep (so Tuesday 29 Sep's open-to-close is a real, tradeable next-day return); the 8 headlines with actual sentiment variation (Fortis Healthcare +0.70, Great Eastern Shipping +0.62, Max Financial +0.38, NSE +0.15, HDFC Bank 0.0, ...) are exactly the ones aligned to Tuesday 29 Sep, whose next-day return (Wednesday 30 Sep) had not traded yet in this fixture. The regressor and the sentiment-bearing headlines never overlap in this snapshot. With zero variance in the predictor, `ols_fit` correctly returns slope = 0.0 (not a divide-by-zero) in both the train and test split, so the fitted line is just "predict the training mean" - out-of-sample R² = 0.000 exactly, and the model's test MAE (0.0096) matches the naive baseline's test MAE (0.0096) to the reported precision, because the two predictions are identical. This is a defined, mechanically correct null - the regression pipeline works and evaluates out of sample honestly - but it cannot test whether sentiment predicts next-day returns on this fixture, because there is currently no version of "next-day return available" that includes a sentiment-bearing headline. Re-running `sentiment.correlate`/`sentiment.regress --live` once Wednesday 30 Sep has traded (or scraping a wider date range) would let the 8 higher-variance headlines into the regression for the first time.

**Day 7 - sentiment-price overlay and cumulative abnormal return charts.** `sentiment/overlay.py` writes two charts to `outputs/` (never committed, per `.gitignore` - see Ground rules). There is no free, fixture-committed NSE benchmark index anywhere in this repo, so `sentiment/market.py` builds a proxy "market" return instead: the equal-weighted mean of the same 23-ticker universe Day 5 already resolved headlines against, on each date. An abnormal return is a ticker's return in excess of that proxy, not the real NSE market - see Limitations for what that substitution costs.

`sentiment_price_overlay.png` plots the full ~1-month cumulative return for the 3 "high-magnitude" tickers Day 5 already identified (Fortis Healthcare, Great Eastern Shipping, Max Financial - the only headlines whose `|compound| > 0.3`), with a marker on each one's aligned headline session. The other 20 resolved headlines are deliberately left off this chart: all 20 share the identical saturated `compound = 0.296` (see Day 5/6 Findings), so a panel per headline would be indistinguishable noise, not a genuine per-headline comparison.

The chart surfaces a concrete case of VADER's already-documented finance-jargon blind spot (Day 2's `finance_jargon` accuracy was 0/6) landing on real price data: `"Fortis Healthcare shares in focus as Supreme Court allows forensic audit to proceed"` scores `compound = +0.70` - VADER's lexicon reads "allows" and "proceed" as positive words with no notion that "forensic audit" is the actual subject - while the stock's cumulative return over the same month is **-10.4%**, and the headline lands right at the bottom of a steep multi-week decline, not a rebound. The other two high-magnitude headlines are more legible: Great Eastern Shipping's headline, a brokerage-commentary summary (`compound +0.62`), sits on a genuinely positive month (+11.2% cumulative, a real uptrend already in progress before the headline), and Max Financial's headline, also brokerage commentary (`compound +0.38`), sits on a choppier but net-positive month (+4.1%). One out of three "positive" headlines by VADER's score is a headline about litigation risk on a stock that fell hard - read as a second, sharper illustration of the same gap Day 2/3 already found with hand-labeled examples, not as a new finding about VADER in general.

`cumulative_abnormal_return.png` aligns each resolved headline to trading-day offsets from its own aligned session (0 = event day) and cumulates abnormal return (vs the equal-weighted proxy) across the default window (-5 to +1 trading days), averaged separately across the high- and low-magnitude groups. The honest result is **not** a clean event-day reaction: the high-magnitude group's mean CAR is already running positive (+2.1% at offset -5) well before offset 0, because two of the three tickers (Great Eastern Shipping, Max Financial) were already in an uptrend before their headline appeared - the group's CAR trajectory reflects pre-existing momentum in 2 of 3 names, not a reaction to news, and Fortis Healthcare's steep decline (the one name where the headline plausibly *should* have mattered, in the wrong direction) is outvoted by the other two in a 3-headline average. With n=3, this cannot support any claim about what high-magnitude sentiment headlines do to abnormal returns on this fixture - the chart is descriptive, and the number of trading days actually observed at each offset varies (documented in `average_car_by_offset`'s docstring): offset +1 has fewer contributing headlines than offset 0, because Tuesday-aligned headlines' next session had not traded yet in this fixture, the same gap Day 5/6 already hit.

**Day 8 - timestamp-shuffle leakage audit.** `sentiment/audit.py` implements the correctness gate directly: for each of `--n-perm` (default 2000) random permutations, it reassigns the 23 resolved headlines' real `published_at` timestamps among each other, re-runs Day 4's `align_headline` and Day 5's price-bar lookup on the shuffled timestamp (not a precomputed return - the actual alignment code, so a bug in that code would show up here too), and recomputes the contemporaneous Pearson r. `sentiment.stats.permutation_p_value` (new) reports the two-sided fraction of that null at least as extreme as the real, true-timestamp r.

**Day 8, second control - `sentiment/leakage_audit.py`.** `sentiment.audit` shuffles the timestamps and tests the contemporaneous correlation only. This module applies the same shuffle to the two signals Day 5 and Day 6 report beyond that, the lagged correlation and the out-of-sample regression R^2, using `correlate.build_rows_from_headlines` so the real alignment and price-lookup code runs on each shuffle. On this fixture the real lagged r (+0.000) and test R^2 (+0.000) sit inside the shuffled-timestamp null (16th and 82nd percentile), so neither passes as a leak. Both of those real values are zero because the fixture has no usable variation, so this control cannot show a real signal vanishing; it only shows nothing newly leak-like appears.

**Day 8, third control - `sentiment/robustness.py`.** The two shuffled-timestamp audits only reshuffle time, so this module checks what they cannot. On the committed fixture (`python -m sentiment.robustness`, 2000 permutations, seed 0): (1) **Reverse causality.** 6 of the 23 resolved headlines name the price move in the title ("shares rise 4%"). Dropping them gives n=17, r=-0.457, 95% CI [-0.769, +0.030] with only 4 distinct sentiment scores. The interval still includes zero and the 17 rows are mostly the one template score, so this is not a finding; it shows the move-naming headlines were not what hid a relationship. (2) **Market-wide shocks.** The 23 returns fall on only 2 sessions. The session-demeaned r is -0.187, almost the raw -0.185, and a permutation that shuffles returns only inside a session (keeping each day's market move in the null) puts the real r at p=0.583, null mean -0.007, std 0.303. Nothing here separates the pairing from chance. (3) **Feed timestamps.** No headline is dated after its scrape, no link repeats with a different time, and no instant carries 5 or more headlines, so those checks pass. The same-title check only flags a repeated title when its distinct published times are *not* already explained by an equal number of distinct links (tightened Day 46, P43) — a recurring daily template ("X Share Price Highlights") reused once per distinct article is expected, correctly-timestamped behavior, not a defect; a genuine same-link retiming under an unchanged title still is flagged. All checks pass clean on this frozen fixture. They also now pass clean on the real, currently-growing corpus (`python -m sentiment.robustness`, no `--in` override, 247 rows as of 22 Oct 2026) — before the Day 46 fix, the untightened check mis-flagged 17 of those rows as "same title, different published time", every one a distinct, correctly-timestamped article reusing a template title on its own distinct link, not a re-timed duplicate. All three results leave the Day 5-8 null as it was.

Run against the committed fixture (`python -m sentiment.audit --n-perm 5000`): real r = **-0.185** (n=23, matching Day 5 exactly, as it must - same alignment code, same prices), shuffle null mean **+0.115**, std **0.120**, **p = 0.28**. Not significant at any conventional threshold: the real pairing is unremarkable against the shuffle-generated null, so there is no detectable look-ahead-driven signal underneath Day 5's near-zero correlation. The result is stable across RNG seeds (p = 0.278-0.286 across three independent 5000-permutation runs with seeds 0/1/2).

One finding from building this control is itself worth recording, not hidden: the shuffle null's mean is **+0.115**, not 0. A generic permutation test on two unrelated continuous variables centers on zero; this one does not, because all 50 scraped headlines were published within roughly 36 hours (28-29 Sep 2026, see Day 1), so every headline's `published_at` falls on essentially one of two calendar days to begin with. Shuffling timestamps *among these headlines* mostly just swaps which of two sessions (Monday's or Tuesday's) each ticker's return is drawn from, not a free re-timing across a real calendar - a narrower, less-independent null than "shuffle headline timestamps" suggests at first read. That narrowness does not invalidate the test (the real pairing is still checked against the actual possible re-pairings this fixture's data supports) but it does mean the null's own non-zero center is a property of the data's limited time span, not evidence of anything - see Limitations and the "why this might be spurious" section below for what that costs the audit's power. A second, independent self-test (`tests/test_audit.py::test_shuffle_destroys_a_true_timestamp_dependent_signal`) proves the mechanism itself has power: a synthetic case engineered so contemporaneous return equals compound only under the true timestamp gets r=1.0 and p≈0.007 - the shuffle correctly flags a genuine timestamp-dependent signal as a significant outlier, so a "pass" on the real fixture is not just a test that can never fail.

## Why this null result might be spurious anyway

The leakage audit passing is necessary, not sufficient - it only rules out one specific failure mode (look-ahead through the timestamp-alignment pipeline). Separately from that, here is why Day 5-7's "no correlation" finding should still be read with real suspicion, written against this repo's own results rather than as a generic disclaimer:

- **The shuffle null itself is narrow.** As the Day 8 finding above shows, every headline comes from a ~36-hour scrape, so "shuffle the timestamps" only ever redistributes headlines across two real sessions, not across a real calendar's worth of independent trading days. A leak that only shows up over a longer horizon, or a subtler timing bug that two sessions happen not to expose, would not necessarily be caught by this fixture's version of the test - the audit's power is bounded by the same narrow data that limits every other day's finding.
- **Multiple tests on an overlapping, tiny sample.** Days 5-7 ran contemporaneous correlation, lagged correlation, an event study, a next-day regression, an overlay chart, and a CAR chart - six analyses, on the same 23 headlines, with the event study/overlay/CAR all keying off the identical 3 "high-magnitude" headlines (Fortis Healthcare, Great Eastern Shipping, Max Financial). A true null finding repeated six ways over the same 3-23 data points is not six independent confirmations; it is one small sample looked at six times, and the 95% CIs reported for each already say so (all comfortably straddle zero), but a reader skimming the headline numbers could easily miss that they are not independent evidence.
- **Saturation cuts the effective sample size further.** 17 of the 23 resolved headlines share the identical VADER compound (0.296, the "Share Price Highlights" template). The contemporaneous correlation's real degrees of freedom are closer to the handful of headlines with distinct scores than to n=23 - which is also *why* the audit's own shuffle null isn't well-mixed (see above): most permutations just reshuffle among near-identical compound values, so even a perfectly engineered leak limited to the saturated majority could hide inside this null's noise rather than standing out from it.
- **The audit covers Day 5's correlation pipeline, not Day 7's overlay/CAR pipeline.** `sentiment.audit` shuffles timestamps through `align_headline` and `sentiment.correlate`'s contemporaneous-return lookup - it does not touch `sentiment/market.py`'s equal-weighted proxy-market construction or `sentiment/overlay.py`'s abnormal-return/offset logic, which have their own, different leak surface (what "market" return a ticker's return is measured against, and how offsets are counted). A clean audit result here says nothing about whether those modules leak.
- **Single source, single scorer in the tested pipeline.** Every headline is Economic Times only (Day 1), and the correlation this audit checks uses VADER's compound, not FinBERT's score - Day 3's FinBERT scores were only ever compared to VADER for agreement, never correlated against returns, so this audit's "no leak" finding is scoped to the one sentiment/return pipeline that was actually built, not to sentiment analysis on this data in general.

None of this reverses Day 5-7's finding or this day's audit result - both still stand as reported. It is the honest accounting of what a passing leakage test does and does not prove, written against this repo's own numbers rather than a template disclaimer.

**Integration day - v0.5 spine contract.** `python -m sentiment.contract --ticker INFY.NS --out outputs/sentiment_contract.json` writes `{"sentiment": {"score_7d", "headline_count_7d", "model", "coverage"}}` for one ticker, averaging VADER `compound` over headlines resolving to it inside a trailing 7-day window of leak-free session dates. `model` is `"vader"`, not FinBERT, because the contract names whichever scorer actually ran. Honest limits: every fixture ticker has one headline, so `score_7d` is a single score and `coverage` is `"partial"`; none of this repo's 23 tickers are in Stock Stalker's 3-ticker fixture universe, so nothing attaches to a live candidate yet. Stock Stalker reads this as a file (`stockstalker.gates.sentiment`), never an import.

## Pre-registered follow-up test

Days 5-8 ran several related tests on one small sample, so a further pass over the same 50 headlines proves nothing. The next test is fixed here, before any new data exists, and is the only one that counts:

- **Hypothesis:** the next session's open-to-close return is positively related to the headline's sentiment score.
- **Statistic:** one Pearson r between FinBERT `compound` and `lagged_return`, with returns demeaned within each session date (`sentiment.robustness.session_demeaned_r` logic) and headlines that name a price move excluded.
- **Data needed before it is run:** at least 100 headlines resolved to a priced ticker, spread over at least 10 sessions, with at least 3 distinct sentiment scores among them. Below that the test is not run and nothing is reported as a result.
- **Decision rule:** two-sided, alpha 0.05, one test so no multiple-testing correction. A confidence interval that includes zero is reported as inconclusive, not as "no effect".
- **Not allowed afterwards:** changing the horizon, threshold, scorer or exclusion rule after seeing the result.

## Limitations and what would make me wrong

- News feeds are edited and deleted, so coverage is partial and not reproducible from the live web. Everything used is snapshotted.
- Coverage is currently one source (Economic Times markets RSS). Moneycontrol blocks robots.txt itself with a 403 and Reuters' feed host is unreachable from this sandbox's network - both are recorded, not silently dropped. A single-source sample cannot support a claim about "headline sentiment" broadly; later days' correlation and event-study work needs to be read against that, or coverage needs to widen first. `collect-headlines.yml` (Day 7 fix-phase) only widens the corpus over time within this one source - it does not add Moneycontrol or Reuters, since neither has ever been legitimately reachable here.
- VADER is a general-purpose lexicon and scores plainly bullish financial phrasing as neutral. Treated as a baseline, not a finance model - Day 2's evaluation harness measures this directly (0/6 on the `finance_jargon` category) rather than asserting it.
- The eval set is 24 hand-labeled headlines I wrote, not an independent or blind-labeled benchmark, and it is small - a category accuracy of 0/6 or 6/6 is a signal, not a precise estimate. It exists to catch regressions and to give Day 3's FinBERT comparison a documented baseline to beat, not to be a rigorous scorer benchmark on its own. The same 24 headlines were also used to pick which model to trust more, so this is not a held-out test set for anything built on top of FinBERT later.
- FinBERT's model weights are not vendored like the VADER lexicon - they are fetched from the HuggingFace Hub on first use (~440 MB) and cached locally. If this sandbox (or CI) ever runs with no network and no pre-populated cache, `sentiment.finbert` and `sentiment.agreement` will fail; unlike Day 1/2's fixture-first offline guarantee, Day 3 needs network at least once. No sandbox this project has run in could install torch at all (see `ci.yml`'s and `finbert-sentiment-contract.yml`'s own CPU-only-wheel comments) - that gap is why the shipped v0.5 contract names `model: "vader"` rather than `"finbert"`, and why Day 7's second workflow runs FinBERT in GitHub Actions specifically, the one place in this project's toolchain that has actually had torch installable.
- FinBERT is not strictly better than VADER: it closes the `finance_jargon` gap completely (0% -> 100%) but loses ground on `general` (100% -> 92.9%), misreading "Bank shares rally on rate cut hopes" as negative. Neither model is a free upgrade over the other across every category.
- The 38% corpus-level agreement rate is descriptive, not a quality metric - the unlabeled 50-headline corpus has no ground truth, so "the models disagree" says nothing about which one is right. A large share of the disagreement traces to a single repeated headline template ("Share Price Highlights"), so the number would move a lot with a different or larger sample.
- The eval set has still not been checked against actual subsequent price moves - only the 23 headlines Day 5 could resolve to a ticker have, and that check found no signal (see Findings).
- Day 6's out-of-sample regression could not actually test the sentiment/next-day-return relationship on this fixture: the 15 headlines with a computable next-day return all happen to be the "Share Price Highlights" template headlines aligned to Monday, which all share the identical VADER compound score - the 8 headlines with real sentiment variation are aligned to Tuesday, whose next-day return (Wednesday) had not traded yet. Out-of-sample R² = 0.000 here means "the regressor had zero variance to work with," not "sentiment has no predictive power" - those are different claims, and only the first is what this run actually shows.
- Day 5's sample is small and lopsided in a way that limits what its null result can mean: 23 headlines, 17 of them tied at the exact same VADER compound score because the dominant headline shape (a "Share Price Highlights" liveblog title) carries almost no distinguishing sentiment content. A wider or more varied headline sample - more days scraped, or a feed with more editorial/opinion content - would give the correlation more independent variation to actually test, and might not replicate a near-zero r.
- Every price return in Day 5 is single-session (open-to-close), from one day's scrape (28-29 Sep 2026) against one day's price snapshot. It is a cross-section across 23 different companies on 1-2 calendar sessions, not a time series across many trading days - a materially different, weaker design than tracking one sentiment/return pair over months, and the confidence intervals reported are exactly that wide because of it.
- Lagged return for the 8 headlines aligned to Tuesday 29 Sep could not be computed at all in this run - their next session (Wednesday 30 Sep) had not traded yet. Re-running `sentiment.correlate --live` a day later would fill that in; the committed fixture snapshot will not, since it is frozen at this run's fetch time.
- `sentiment/tickers.py` is a closed, hand-written lookup covering only the headline shapes in this repo's one committed fixture - it does not generalize to a new scrape without new rules being added on purpose, by design (see the module's own docstring for why a fuzzy matcher was rejected).
- `market_hours.is_trading_day` is weekday-only - there is no NSE holiday calendar. A headline published on an actual market holiday (e.g. a Monday that NSE has closed for a festival) is wrongly treated as a trading day and aligned one session too early. Free NSE holiday-calendar data exists but has not been wired in yet; until it is, `session_date` should be read as "the next weekday", not "the next actual trading day", on the handful of days a year that differ.
- The alignment rule is deliberately conservative for intraday headlines: a headline published at 14:00 IST still has 90 minutes of the same session left to react in, but this module rolls it all the way to the next day rather than trying to use the partial remainder of today's session - there is no intraday price fixture in this repo to test a same-day partial reaction against, and guessing without one would be exactly the kind of unverified number this portfolio avoids.
- Correlation over a short window with many tested horizons manufactures significance. The hypothesis is fixed before the data is touched.
- Day 7's "market" is a proxy, not a real benchmark: the equal-weighted mean return of the same 23-ticker universe Day 5 resolved headlines against, because no free NSE index fixture (NIFTY 50 or similar) is committed to this repo. Abnormal return here means "in excess of this specific 23-name sample," which is itself sentiment-selected, not "in excess of the market" in the usual sense - a real index would need a new data source wired in first.
- The cumulative abnormal return chart's high-magnitude group has n=3 - the same 3 headlines Day 5's event study already used, because they are the only ones in this fixture that are not saturated at `compound = 0.296`. A 3-headline average cannot support a causal claim about sentiment and abnormal returns; the chart is a descriptive trajectory, not a tested effect, and one bad-fit case (Fortis Healthcare, see Findings) is outvoted by two better-fit ones in the average.
- The number of headlines contributing to the CAR average is not constant across the offset window: offsets near the edge of the fixture's date range (particularly +1 for Tuesday-aligned headlines) have fewer contributing headlines than offset 0, the same "next session hasn't traded yet" gap Day 5/6 already documented.
- Day 8's leakage audit (`sentiment.audit`) shuffles timestamps only through Day 5's contemporaneous-return pipeline, not through Day 7's proxy-market/overlay/CAR code, which has its own different leak surface (see "Why this null result might be spurious anyway"). Its shuffle null is also narrower than "randomise the timestamp" suggests: every headline comes from one ~36-hour scrape, so a shuffle mostly reassigns headlines between two real sessions, not across a free calendar - the null's own mean (+0.115, not 0) is a direct symptom of that, not a sign of anything wrong.
- `.github/workflows/ci.yml` now runs the full suite (with CPU torch) and the three audit CLIs on every push to `main` and every pull request, so "runs in CI, not once by hand" is true. The live-data paths are still not exercised there. A trading-day count is printed alongside the CLI's offset-0 summary but not shown per-point on the chart itself.
- **The checks in `sentiment/robustness.py` are narrow.** The move-naming filter is a regular expression on the title, so it misses a headline that implies a move without a percentage and may flag a forecast phrased like a move. The within-session permutation scrambles which return each headline gets, but not which 23 of the 50 headlines enter the analysis; that choice is still made by hand-written matching rules in `sentiment/tickers.py` and a bias there is not tested.
- **With 2 sessions, demeaning removes 2 means from 23 points.** That is the most a market-wide shock can be separated out on this fixture. The Fisher-z interval on r still treats the 23 pairs as independent, so it understates how little the sample can rule out.
- **The timestamp checks only catch internal inconsistency.** A feed that consistently backdates or republishes every headline passes them. The `pubDate` values are Economic Times' own, and nothing here verifies them against an independent source.
- **The two Day 7 collection workflows push straight to `main`, with no review step** - the same pattern every other data-fetching workflow in this portfolio uses (`daily-snapshot.yml` in STOCKSTALKER/implied-vol-surface), not something special to this repo. `finbert-sentiment-contract.yml` only regenerates the contract for the one ticker (INFY.NS) the v0.5 integration day already verified resolves headlines in this fixture; a new ticker needs a new `--ticker`/`--out` pair added by hand, it is not discovered automatically. Growing the corpus (daily) and regenerating the FinBERT contract (weekly) run on different schedules, so the contract can lag the corpus by up to a week between weekly runs - acceptable for a 7-day trailing window, but worth naming.

```json
{
  "sentiment": {
    "score_7d": null,
    "headline_count_7d": 0,
    "model": "vader",
    "coverage": "none"
  }
}
```

Every field is empty because the INFY-resolved headline has aged out of the trailing 7-day window as the corpus grew past its original September snapshot — not a bug, the window is supposed to forget old headlines.

Communication is by file contract, not imports, so either side can be refactored without breaking the other.
